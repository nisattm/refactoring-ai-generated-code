# Refactoring AI-Generated Code

Comparing three ways of letting an LLM refactor its own code: **Single LLM**, **Iterative LLM** and **Multi-Agent**. We measure how much each approach improves code quality, whether it preserves behavior, and what it costs.

**Course:** Engineering Design II – Project 02: Refactoring AI-Generated Code (Sustainable Software Engineering)

## Research questions

| | Question | Metrics |
| --- | --- | --- |
| RQ1 | How do the three approaches change the maintainability and design quality of Python code generated by Claude? | Size, complexity, design, duplication, logic and architecture metrics ([`docs/metrics.md`](docs/metrics.md)) |
| RQ2 | To what extent do the approaches preserve the behavior of the code? | Held-out tests pass; share of successful refactorings |
| RQ3 | Is the extra token use and time worth the higher quality? | Tokens, time and equivalent cost (estimated at API list price) per successful refactoring |
| RQ4 | How do the quality changes of each approach differ across the parts of the system classified as simple, medium and complex? | Metrics broken down by module and complexity level of the one refactored project |

RQ4 was revised on 29 October 2026: the dataset is one Library Management System refactored as a whole, so complexity levels are a classification of its modules, not separate tasks ([`docs/decisions/002`](docs/decisions/002-single-lms-claude-code.md)).

Research gap: no study we reviewed compares single-shot, iterative and multi-agent refactoring under equal feedback and equal round budgets, with behavior tests and cost measured together. See [`docs/literature/`](docs/literature/).

## Setup

- **Language:** Python 3.14 (latest patch, pinned at setup); FastAPI, Pydantic v2, SQLAlchemy 2.x, SQLite
- **Model:** Claude Sonnet 5.5, the same model for code generation and for all three approaches
- **Access:** Claude Code with a Claude Pro subscription (no API)
- **Subject code:** one **Library Management System** (about 30,000–40,000 lines, REST API, no frontend), generated by Claude piece by piece; its 14 modules are classified as simple, medium or complex ([`dataset/`](dataset/))
- **Refactoring:** the whole project is refactored in one run by each approach

Decisions: [`docs/decisions/002`](docs/decisions/002-single-lms-claude-code.md).

## The three approaches

| | Single LLM | Iterative LLM | Multi-Agent |
| --- | --- | --- | --- |
| In Claude Code | One `claude -p` run | One session | Three subagents (Analyzer, Refactoring, Reviewer) |
| Flow | One message | Find → fix → check | Analyzer → Refactoring → Reviewer |
| Max fix rounds | 1 | 3 | 3 (1 refactoring + up to 2 Reviewer returns) |
| Test feedback | No | Yes | Yes |

Fairness rule: Iterative and Multi-Agent get the same test feedback and the same round budget, so the only difference between them is one conversation versus three roles. Full rules: [`docs/approaches.md`](docs/approaches.md).
