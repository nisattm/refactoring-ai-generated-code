# Refactoring AI-Generated Code

Comparing three ways of letting an LLM refactor its own code: **Single LLM**, **Iterative LLM** and **Multi-Agent**. We measure how much each approach improves code quality, whether it preserves behavior, and what it costs.

**Course:** Engineering Design II – Project 02: Refactoring AI-Generated Code (Sustainable Software Engineering)

## Research questions

| | Question | Metrics |
| --- | --- | --- |
| RQ1 | How do the three approaches change the maintainability and design quality of Python code generated by Claude? | Size, complexity, design, duplication and logic metrics ([`docs/metrics.md`](docs/metrics.md)) |
| RQ2 | To what extent do the approaches preserve the behavior of the code? | All tests pass; share of successful refactorings |
| RQ3 | Is the extra token, money and time spent worth the higher quality? | Tokens, USD and time per successful refactoring |
| RQ4 | How does task complexity (simple / medium / complex) affect quality, behavior and cost? | All metrics by complexity level |

Research gap: no study we reviewed compares single-shot, iterative and multi-agent refactoring under equal feedback and equal round budgets, with behavior tests and cost measured together. See [`docs/literature/`](docs/literature/).

## Setup

- **Language:** Python
- **Model:** Claude, the same model and version for code generation and for all three approaches (version fixed in [`docs/decisions/`](docs/decisions/))
- **Access:** Anthropic API with our own Python orchestration (proposal)
- **Subject code:** tasks at three complexity levels plus a complex **Library Management System**, all generated by Claude ([`dataset/`](dataset/))

## The three approaches

| | Single LLM | Iterative LLM | Multi-Agent |
| --- | --- | --- | --- |
| Conversations | 1 | 1 | 3 (Analyzer, Refactoring, Reviewer) |
| Flow | One message | Find → fix → check | Analyzer → Refactoring → Reviewer |
| Max fix rounds | 1 | 3 | 3 (1 refactoring + up to 2 Reviewer returns) |
| Test feedback | No | Yes | Yes |

Fairness rule: Iterative and Multi-Agent get the same test feedback and the same round budget, so the only difference between them is one conversation versus three roles. Full rules: [`docs/approaches.md`](docs/approaches.md).
