# P2 – Absence tracking

Copy everything between the two lines below and send it as one message. Do not change, add or remove anything.

---

Add absence tracking to the existing course tracking application. All existing endpoints must keep working exactly as before, and the API conventions already used in the application (JSON field names, status codes, error body) also apply to the new endpoints.

There is no enrollment step: absences can be recorded for any existing student in any existing course.

## Absence records

| Field | Type | Rules |
| --- | --- | --- |
| `id` | integer | Generated by the server |
| `studentId` | integer | Taken from the path; ignored in the request body |
| `courseId` | integer | Taken from the path; ignored in the request body |
| `date` | string | Required; a valid date in `YYYY-MM-DD` format |
| `hours` | integer | Required; at least 1 and at most the course's `weeklyHours` |

Several records may have the same date.

Example response:

```json
{
  "id": 7,
  "studentId": 1,
  "courseId": 1,
  "date": "2026-10-12",
  "hours": 2
}
```

| Endpoint | Success | Errors |
| --- | --- | --- |
| `POST /api/students/{studentId}/courses/{courseId}/absences` with body `{ "date": ..., "hours": ... }` | 201, created record | 404 student or course does not exist; 400 invalid |
| `GET /api/students/{studentId}/courses/{courseId}/absences` | 200, records sorted by `date` ascending, then `id` ascending | 404 student or course does not exist |
| `DELETE /api/students/{studentId}/courses/{courseId}/absences/{absenceId}` | 204 | 404 student, course or record does not exist; 404 if the record belongs to a different student or course |
| `GET /api/students/{studentId}/courses/{courseId}/absence-status` | 200, absence status | 404 student or course does not exist |

Deleting a student also deletes all of that student's absence records. Deleting a course also deletes all absence records for that course.

## Absence status

Example response:

```json
{
  "studentId": 1,
  "courseId": 1,
  "totalCourseHours": 42,
  "allowedAbsenceHours": 13,
  "totalAbsenceHours": 10,
  "remainingAbsenceHours": 3,
  "status": "WARNING"
}
```

Calculation:

1. `totalCourseHours` = `weeklyHours` × semester weeks.
2. The absence limit percentage is the theoretical limit for `THEORETICAL` courses and the practical limit for `PRACTICAL` courses.
3. `allowedAbsenceHours` = `totalCourseHours` × limit percentage / 100, rounded up to the next whole number. The result must be exact: 42 × 30 / 100 = 12.6 → 13; 42 × 20 / 100 = 8.4 → 9; 70 × 20 / 100 = 14 → 14.
4. `totalAbsenceHours` = sum of `hours` of all records of this student in this course; 0 if there are none.
5. `remainingAbsenceHours` = `allowedAbsenceHours` − `totalAbsenceHours`, but never below 0.
6. `status`:
   - `FAILED` if `totalAbsenceHours` > `allowedAbsenceHours`
   - otherwise `WARNING` if `totalAbsenceHours` > 0 and `allowedAbsenceHours` − `totalAbsenceHours` ≤ warning margin
   - otherwise `NORMAL`

Changing a course's `type` or `weeklyHours` does not change existing absence records; the status is always calculated from the current course values.

## Configuration

These values must be read from `application.properties` and must be changeable there without changing code. The defaults are:

```properties
coursetracker.semester-weeks=14
coursetracker.absence.theoretical-limit-percent=30
coursetracker.absence.practical-limit-percent=20
coursetracker.absence.warning-margin-hours=3
```

## Examples with the default configuration

| Course | `totalCourseHours` | `allowedAbsenceHours` | `totalAbsenceHours` → `status` |
| --- | --- | --- | --- |
| THEORETICAL, 3 hours/week | 42 | 13 | 0 → NORMAL, 9 → NORMAL, 10 → WARNING, 13 → WARNING, 14 → FAILED |
| PRACTICAL, 3 hours/week | 42 | 9 | 5 → NORMAL, 6 → WARNING, 9 → WARNING, 10 → FAILED |
| THEORETICAL, 1 hour/week | 14 | 5 | 1 → NORMAL, 2 → WARNING, 5 → WARNING, 6 → FAILED |
| PRACTICAL, 1 hour/week | 14 | 3 | 0 → NORMAL, 1 → WARNING, 3 → WARNING, 4 → FAILED |
