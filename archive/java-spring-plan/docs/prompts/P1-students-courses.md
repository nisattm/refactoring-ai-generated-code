Build a REST API for a university course tracking system. In this first step, implement student and course management.

## Technical requirements

- Java 17 or newer, Spring Boot 3.x, Maven.
- Maven coordinates: groupId `edu.abu`, artifactId `course-tracker`.
- Root package: `edu.abu.coursetracker`. The `@SpringBootApplication` class must be in this package.
- Use an H2 in-memory database. Data does not need to survive a restart.
- The application must start with `mvn spring-boot:run` on port 8080, and `mvn package` must succeed.
- Provide Swagger UI at `/swagger-ui.html` using springdoc-openapi.
- No authentication, no user interface, no external services.

## API conventions

- All endpoints are under `/api`.
- Request and response bodies are JSON. Field names are camelCase exactly as written below. Unknown fields in a request body are ignored.
- Ids are positive integers generated by the server. An `id` sent in a request body is ignored.
- Lists are returned as plain JSON arrays. An empty list is `[]`.
- Status codes:
  - 200 for a successful read or update
  - 201 for a successful creation; the body contains the created resource
  - 204 for a successful delete, with an empty body
  - 400 for validation failures, malformed JSON, invalid enum values, wrong types or a non-numeric path id
  - 404 when a resource referenced by the path does not exist
  - 409 for uniqueness violations or changes that conflict with existing data
- If a path refers to a resource that does not exist, return 404 even if the request body is also invalid.
- Every 400, 404 and 409 response has this body:

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "Student with id 42 not found"
}
```

`status` is the HTTP status code, `error` is the standard reason phrase (`Bad Request`, `Not Found` or `Conflict`), and `message` is a non-empty, human-readable explanation.

## Students

| Field | Type | Rules |
| --- | --- | --- |
| `id` | integer | Generated by the server |
| `studentNumber` | string | Required; exactly 9 digits; unique across all students |
| `firstName` | string | Required; not blank; at most 50 characters |
| `lastName` | string | Required; not blank; at most 50 characters |
| `email` | string | Required; a well-formed email address |

Example response:

```json
{
  "id": 1,
  "studentNumber": "220201001",
  "firstName": "Ayşe",
  "lastName": "Yılmaz",
  "email": "ayse.yilmaz@example.com"
}
```

| Endpoint | Success | Errors |
| --- | --- | --- |
| `POST /api/students` | 201, created student | 400 invalid; 409 `studentNumber` already used |
| `GET /api/students` | 200, all students sorted by `id` ascending | — |
| `GET /api/students/{id}` | 200, the student | 404 |
| `PUT /api/students/{id}` (full replacement, same body as POST) | 200, updated student | 404; 400 invalid; 409 `studentNumber` used by another student |
| `DELETE /api/students/{id}` | 204 | 404 |

## Courses

| Field | Type | Rules |
| --- | --- | --- |
| `id` | integer | Generated by the server |
| `code` | string | Required; 2–10 characters; only uppercase letters A–Z and digits; unique across all courses |
| `name` | string | Required; not blank; at most 100 characters |
| `type` | string | Required; `THEORETICAL` or `PRACTICAL` |
| `weeklyHours` | integer | Required; 1 to 10 inclusive |
| `gradingScheme` | string | Required; `MIDTERM_FINAL` or `MIDTERM_PROJECT_FINAL` |

Example response:

```json
{
  "id": 1,
  "code": "SE402",
  "name": "Engineering Design II",
  "type": "THEORETICAL",
  "weeklyHours": 3,
  "gradingScheme": "MIDTERM_PROJECT_FINAL"
}
```

| Endpoint | Success | Errors |
| --- | --- | --- |
| `POST /api/courses` | 201, created course | 400 invalid; 409 `code` already used |
| `GET /api/courses` | 200, all courses sorted by `id` ascending | — |
| `GET /api/courses/{id}` | 200, the course | 404 |
| `PUT /api/courses/{id}` (full replacement, same body as POST) | 200, updated course | 404; 400 invalid; 409 `code` used by another course |
| `DELETE /api/courses/{id}` | 204 | 404 |
