## Shared context block (everyone copies this first)

```
I am a final-year software engineering student. My team of five is doing a course project called "Refactoring AI-Generated Code" (Engineering Design II).

Our project:
- Three LLM coding agents (Claude via Claude Code, GPT via Codex, Gemini via Antigravity) each generate the same small Java 17 / Spring Boot 3 REST API (students, courses, absences, grades, student report) from the same six neutral prompts: four feature prompts (P1–P4) and two change requests (DT1, DT2) that modify requirements after delivery.
- We measure technical debt in each generated codebase with CK, DesigniteJava, PMD/CPD, SonarCloud and multimetric (maintainability index, Halstead), and performance with JMH.
- We lock behavior with tests (JUnit 5, MockMvc, ApprovalTests, jqwik; coverage with JaCoCo, mutation testing with PIT), then refactor in small IDE-supported steps, detect applied refactorings with RefactoringMiner, and compare metrics before and after.
- Research questions: (RQ1) Which code smells and technical debt appear in code generated by different LLMs, and how do they grow with change requests? (RQ2) How much does safe, test-protected refactoring improve the metrics?

I need a literature survey for a presentation. Rules you must follow:
1. Only cite real, published, verifiable sources: peer-reviewed conference or journal papers (ICSE, FSE, ASE, MSR, ICSME, SANER, SCAM, TOSEM, TSE, EMSE, JSS, IST, etc.) or arXiv preprints (mark these as "preprint"). Industry reports are allowed only if marked "industry report".
2. Prefer 2022 and later. Older work only if it is foundational (e.g. Fowler's code smell catalog).
3. For every source give: authors, year, title, venue, DOI or URL.
4. Never invent numbers. Every number must come from the paper; say where (section, table or page). If you are not sure, write "not verified".
5. If you cannot find a source for something, say so instead of guessing.
6. Write the output in English.
```

My part of the survey covers S3 (code smells) and S4 (function call and structural problems).

S3 – Which code smells appear in AI-generated code?
- Which smells were found (Long Method, Large/God Class, Duplicate Code, Feature Envy, Long Parameter List, Magic Number, Dead Code, Complex Conditional, Data Class, etc.) and how often?

S4 – Problems caused by function calls and code structure

- Database access patterns in generated web/backend code: queries inside loops (N+1), loading whole tables, missing transactions.
- Error handling problems: swallowed exceptions, generic catch blocks, inconsistent error responses.
- Did these structural issues cause measurable bugs or performance problems?
