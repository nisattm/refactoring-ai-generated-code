# Dataset

One Library Management System (LMS), generated by Claude Code (Claude Sonnet 5.5) and then refactored as a whole by the three approaches (Week 3). Decision: [`../docs/decisions/002`](../docs/decisions/002-single-lms-claude-code.md).

> **This file is not given to the model.** Level labels and expected smells would act as quality hints. Only `lms/requirements.md` is used in generation prompts.

## Why one system

The instructor asked for large, complex code in which all metrics can be measured, and for one refactoring of the whole project, because the modules depend on each other. Week 3 asks for the dataset to be classified as simple, medium and complex; we classify the **modules** of the LMS.

## Modules and complexity levels

Levels are calculated from the requirements document ([`lms/requirements.md`](lms/requirements.md), v0.6) with this score:

| Criterion | 0 points | 1 point | 2 points |
| --- | --- | --- | --- |
| Business rules (requirement IDs of the module itself) | 0–9 | 10–13 | 14+ |
| Modules it depends on ([table below](#cross-module-dependencies)) | 0–2 | 3–5 | 6+ |
| State transitions (status fields of the module's entities) | None | Simple (2 states) | Several states |

Total 0–1 = simple, 2–3 = medium, 4–6 = complex. Each level must contain at least 2 modules.

- **Calibration (30 October 2026, before any code exists):** the first thresholds (rules 0–5 / 6–12 / 13+, dependencies 0–1 / 2–3 / 4+) gave 1 simple, 4 medium and 9 complex modules, because 10 of 14 modules reached the dependency maximum. The thresholds above were set to meet the rule of at least 2 modules per level. Recorded in [`../docs/decisions/002`](../docs/decisions/002-single-lms-claude-code.md).
- **Common requirements** (LIB-TECH, LIB-COM, LIB-IF, 54 IDs) belong to no module and are not counted in any score. Their tests live in the Core test files.
- After generation, CC, fan-out and SLOC are reported per level to show whether the labels match the measured code. Test results are also reported per case type (Normal, Boundary, Error, Property, Scenario) from the `Type` column of the case tables.

## Metric coverage matrix

Every metric and smell must have at least one module whose **requirements** give it a chance to occur; otherwise refactoring could not change it. The matrix lists the requirement features that create the opportunity. Nothing here is told to the model; whether the smell actually appears is measured after generation ([`../docs/smell-catalog.md`](../docs/smell-catalog.md#observed-smells-after-generation)).

| Metric / smell | Opportunity in the requirements | Modules |
| --- | --- | --- |
| Size, CC, Cognitive Complexity, nesting (S01, S09, S10) | Ordered check sequences with many outcomes (LIB-LOAN-05, LIB-LOAN-07, LIB-RES-02, LIB-AUTH-11) | 2, 5, 6 |

## Business rules (approved 29 October 2026)

Summary only. The binding specification, including all further rules, endpoints and error codes, is [`lms/requirements.md`](lms/requirements.md).

| Membership type | Loan period | Limit | Renewals | Late fee |
| --- | --- | --- | --- | --- |
| Student | 14 days | 5 | 1 | 2 TL/day |
| Academic | 30 days | 10 | 2 | 1 TL/day |
| Staff (university administrative staff) | 21 days | 7 | 2 | 1 TL/day |
| Guest | 7 days | 2 | 0 | 5 TL/day |

- **Working day:** not Saturday, Sunday or an official holiday (2026–2027 list in the requirements, cross-checked in two published lists; not yet checked against the Official Gazette). Half-day eves (arife) are working days.
- **Due date:** loan period in calendar days; if the due date is not a working day, it moves to the next working day.
- **Late fee:** starts the day after the due date; working days only; capped at 100 TL per book; amounts use `Decimal`.
- **Block:** a member with total debt of 50 TL or more cannot borrow.
- **Renewal:** new period starts on the renewal day; overdue books cannot be renewed; books with an active reservation cannot be renewed.
- **Reservations:** at most 3 active per member; a ready book not collected within 3 working days passes to the next member.
- **Lost book:** late fee accrued until the loss is reported + book price + 25 TL handling fee.
- **Fee cap:** 100 TL per book, independent of the book's price.
- **Reservation passes on:** when a ready book is not collected in time and passes to the next member, a notification record is created (module 8).
- **Transfer between branches:** 2 working days. A reserved book in transfer counts as "ready" only when it arrives at the pickup branch.

## Generation rules

- Code is generated piece by piece with Claude Code; generated code is never edited by hand.
- **Integration errors** (wrong imports, mismatched interfaces between pieces) are fixed only with an additional prompt. Every such prompt and its output are stored in `prompts/` and `generation-log.md`, and their tokens are added to the generation cost.

```
dataset/

    ├── generated/           Code as generated (never edited by hand); tagged v0-ai-baseline

    │   ├── feedback/        Tests whose results the LLM sees

```
