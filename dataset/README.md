# Dataset

Tasks whose Python code is generated by Claude and then refactored by the three approaches (Week 3).

## Complexity levels

| Level | Definition | Example |
| --- | --- | --- |
| Simple | One function or one class | Late fee calculation |
| Medium | 2–4 classes with connected business rules | Loan and reservation rules |
| Complex | Multi-module system | Library Management System: members, catalog, loans, reservations, fines, notifications, reports, search |

Tasks are chosen so that the smells in [`../docs/smell-catalog.md`](../docs/smell-catalog.md), especially design and logic smells, can occur; otherwise the effect of refactoring cannot be measured. The number of tasks per level is decided in the metrics meeting.

## Structure of a task

```
dataset/
└── <level>/<task-id>/
    ├── requirements.md     Functional requirements
    ├── prompt.md           Exact generation prompt
    ├── generation-log.md   Model, version, date, settings, tokens
    ├── generated/          Code as generated by Claude (never edited by hand)
    ├── tests/
    │   ├── cases.md        Test case table (see docs/testing.md)
    │   ├── feedback/       Tests whose results the LLM sees
    │   └── heldout/        Tests used only for evaluation
    ├── inputs/             Measurement inputs: small, medium, large
    └── baseline.csv        Metrics before refactoring (Week 4)
```
